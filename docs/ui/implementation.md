# UI 구현 메모

브랜치: `production-transition` · 기준 디자인: `prototype-v3-dark.png`

## 이번 구현

무채색의 어두운 화면을 기본으로 하고 같은 배치의 밝은 테마를 제공한다. 반투명 효과는 사이드바와 대화상자에 제한한다. 테마만 브라우저에 저장하며 분석 데이터는 저장하지 않는다.

| 화면 | 확인할 수 있는 동작 |
|---|---|
| 홈 | 소개, 샘플 탐색, 로그인 연결 예정 안내 |
| 내 분석 | 기업·직무 검색, 정렬, 폴더/목록 전환, 결과 열기 |
| 기업 브리프 | 내용 탭, 근거별 예시 페이지·강조 구절 이동, JSON 다운로드 |
| 내 자료 | CV/JD 탭, 연결된 분석 확인, 샘플 삭제·영향 안내 |
| 내 경험 연결 | CV/JD 선택, 저장 결과와 다른 입력 구분, 기여·준비·근거 탐색 |
| 기업 비교 | 최대 3개 대상 선택, 다른 CV 경고, JD 없음 표시, 공통 항목 비교 |

API는 고정된 가상 예시만 제공한다. 로그인하지 않은 실제 사용자 문서나 결과는 취급하지 않는다. 예시 문서 화면은 HTML이며 PDF 렌더링이 아니다. 실제 업로드·분석 버튼은 미연결 안내로 끝난다. 삭제는 브라우저 메모리에만 반영되며 새로고침하면 복원된다. 삭제된 CV/JD에 연결된 개인화 예시는 숨기고 기업 브리프는 보존한다.

`?view=workspace`, `?view=brief&company=company-a`처럼 화면 URL과 브라우저 뒤로가기를 지원한다. 실제 인증·권한 검사는 다음 단계에서 서버에 구현해야 한다.

## 구조

- `frontend/src/pages/`: 6개 화면
- `frontend/src/components/`: 공통 탐색·대화상자·근거 버튼
- `frontend/src/domain.ts`: 비교 선택, 입력 차이, 샘플 삭제 규칙
- `frontend/src/styles.css`: 테마·반응형 스타일
- `backend/app/`: 헬스체크·샘플 워크스페이스·로그인 미연결 상태
- 기존 루트의 Agent와 Streamlit은 이번 UI에서 호출하지 않는다.

## 다음 작업 순서

1. 화면을 함께 검토해 배치·문구 확정.
2. 상협님과 Agent 입력·출력 계약 합의: 보고서·CV·JD 식별자, 기업 fact, 기여 결과, 근거 ID·쪽수, 누락값, 오류·진행 상태. 기존 결과가 Markdown이면 어댑터로 다루고 팀원 Agent를 임의 수정하지 않는다.
3. Google 로그인·세션과 사용자별 자료/결과 저장을 연결. 관계형 DB와 원본 파일 저장소는 구체 제품을 확정한 뒤 도입.
4. 인증된 PDF 업로드·삭제, 실제 원문 뷰어와 근거 이동 구현.
5. LangGraph 분석 실행·진행/오류 조회, 기존 Agent 어댑터 연결.
6. ChromaDB의 근거 검색과 Docker 실행 구성·README 완성.

2차 요구 기술 중 이번에 들어간 것은 FastAPI이며, LangGraph·ChromaDB·Docker 도입 완료로 간주하지 않는다.
