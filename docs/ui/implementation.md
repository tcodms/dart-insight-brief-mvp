# UI 구현 메모

현재 서비스 동작: 샘플 모드·전환 버튼을 제거하고 실제 계정 자료만 표시한다. 기존 `demo=1` URL도 개인 공간으로 처리한다. 로그인 확인 중에는 대기 화면을 표시해 샘플/소개 화면이 잠깐 노출되는 일을 막는다. 아래 초기 샘플 구현 기록은 디자인 개발 이력이며 현재 서비스 진입 경로가 아니다.

최소 수동 확인은 **PDF 등록 → 기업 분석 시작 → 완료 결과 확인** 3단계다. 로그인 세션이 유지되어 있으면 다시 로그인할 필요가 없다. 로그인부터 확인하려면 로그아웃을 한 번 누른다. CV·JD 기여 입력은 완성된 브리프가 있을 때 표시한다.

브랜치: `production-transition` · 기준 디자인: `prototype-v3-dark.png`

## 이번 구현

무채색의 어두운 화면을 기본으로 하고 같은 배치의 밝은 테마를 제공한다. 반투명 효과는 사이드바와 대화상자에 제한한다. 테마만 브라우저에 저장하며 분석 데이터는 저장하지 않는다.

| 화면 | 확인할 수 있는 동작 |
|---|---|
| 홈 | 소개, 샘플 탐색, 로그인 연결 예정 안내 |
| 내 분석 | 기업·직무 검색, 정렬, 폴더/목록 전환, 결과 열기 |
| 기업 브리프 | 내용 탭, 근거별 예시 페이지·강조 구절 이동, JSON 다운로드 |
| 내 자료 | CV/JD 탭, 연결된 분석 확인, 샘플 삭제·영향 안내 |
| 내 경험 연결 | CV/JD 선택, 저장 결과와 다른 입력 구분, 기여·준비·근거 탐색 |
| 기업 비교 | 최대 3개 대상 선택, 다른 CV 경고, JD 없음 표시, 공통 항목 비교 |

샘플 모드는 고정된 가상 예시를 제공한다. 예시 문서 화면은 HTML이며 PDF 렌더링이 아니다. 샘플 삭제는 브라우저 메모리에만 반영되며 새로고침하면 복원된다. 삭제된 CV/JD에 연결된 개인화 예시는 숨기고 기업 브리프는 보존한다.

2026-10-28: Google 로그인 연결 코드와 개인 자료 관리 화면을 추가했다. 인증 설정 후에는 실제 PDF를 계정별로 저장·조회·다운로드·삭제할 수 있다. 개인 공간에는 샘플 기업 분석을 표시하지 않는다. 샘플 탐색은 별도 전환하며 `demo=1`로 구분한다. OAuth 설정 전에는 로그인 버튼을 비활성화하고 설정 대기를 안내한다. 실제 Google 로그인은 인증 정보 등록 후 확인해야 한다.

같은 날 Agent 연결을 추가했다. 개인 작업 공간에서 사업보고서를 선택해 기업 분석을 시작하고, 완성된 브리프·CV·JD·직무로 기여 분석을 실행한다. 서버 진행 상태를 조회하고 실제 Markdown 결과와 기업 원문 근거를 표시한다. 기여 보고서 2~3개를 나란히 읽는 비교도 연결했으며 구조화된 항목별 비교는 아직 없다.

`?view=workspace`, `?view=brief&company=company-a`처럼 화면 URL과 브라우저 뒤로가기를 지원한다. 실제 PDF의 인증·소유권·변경 요청 검사는 FastAPI에서 수행한다.

## 구조

- `frontend/src/pages/`: 6개 화면
- `frontend/src/components/`: 공통 탐색·대화상자·근거 버튼
- `frontend/src/domain.ts`: 비교 선택, 입력 차이, 샘플 삭제 규칙
- `frontend/src/styles.css`: 테마·반응형 스타일
- `backend/app/`: 인증·문서 관리·분석 작업·LangGraph 흐름·결과 저장
- `frontend/src/components/AnalysisPanel.tsx`: 실제 분석 실행·진행·결과·보고서 비교
- 기존 루트의 Agent 파이프라인을 격리된 프로세스에서 호출한다. Streamlit 화면은 호출하지 않는다.

## 다음 작업 순서

1. 화면을 함께 검토해 배치·문구 확정.
2. 상협님과 Agent 입력·출력 계약 합의: 보고서·CV·JD 식별자, 기업 fact, 기여 결과, 근거 ID·쪽수, 누락값, 오류·진행 상태. 기존 결과가 Markdown이면 어댑터로 다루고 팀원 Agent를 임의 수정하지 않는다.
3. 실제 사업보고서로 전체 기업 브리프 흐름과 원문 PDF 표시를 브라우저에서 검증.
4. JD 없는 기여 분석 지원 방식과 기여 결과의 구조화된 비교 형식 합의.
5. 서버 중단·재시도·실패 사례를 보완하고 SSE 등 진행 조회 방식 검토.
6. ChromaDB의 근거 검색과 Docker 실행 구성·README 완성.

FastAPI와 LangGraph의 기본 실행 흐름을 도입했다. LangGraph의 체크포인트 재개·ChromaDB·Docker는 후속 작업이다.
