# 멘토 미팅 메모 · 2026-10-29

30분: 현황·피드백 5분 / Agent 구조·처리 시간 7분 / 질문 15분 / 우선순위 정리 3분.

## 처음 설명할 말

사업보고서를 요약하는 데서 나아가, 기업의 사업·전략과 지원자의 CV·JD를 연결해 자소서·면접에 활용할 기여 보고서를 만들고 있습니다. React·FastAPI·SQLite로 로그인·자료 관리·실제 Agent 실행과 결과 저장까지 연결했습니다.

## 피드백 반영 현황

| 피드백 | 반영한 것 | 남은 것 |
|---|---|---|
| 단순 요약과의 차별화·CV 개인화 | CV·JD와 기업 fact를 합친 기여 보고서 생성 연결. 합성 자료로 실제 호출 성공 | 실제 지원 사례의 유용성 검증 |
| 원문 위치 표시 | fact의 쪽수·절·인용 저장, PDF 페이지 이동 연결 | 모든 브리프 사실·기여 판단과 출처를 직접 연결 |
| 비교 판단 기준 | 내 경험 × 기업 사업·전략 × JD 요건 중심으로 정의. 공식 비전·인재상은 보조 기준 | 공통 항목 비교표. 현재는 보고서 원문 나란히 보기 |
| 여러 기업 비교·대표 사례 | 2~3개 기여 보고서 선택과 CV 차이 안내 | 대표 기업 2~3개로 근거·판단 검증 |
| OpenDART | 자동 수집은 현재 범위에서 제외하고 수동 업로드로 결정 | 후속 확장 항목 |

## Agent를 나눈 이유

- 기업 분석: **사업·전략 / 재무·경영 / 인력·조직**을 3개 Agent로 병렬 추출 → **기업 브리프 Agent 1개**.
- 개인화: **CV Agent 1개 + JD Agent 1개**로 지원자 경험·직무 요건을 구분 → 기업 fact와 합쳐 **기여 Agent 1개**.
- 총 **7개 구성**이지만 동시에 7개를 실행하는 것은 아님. 기업 브리프 4회, 기여 분석 3회 호출이며 CV·JD는 현재 순차 실행.
- 영역별 입력을 줄이고 추출 형식을 고정하며, 기업 fact JSON을 브리프·개인화에서 재사용하려는 설계. 분리 자체의 품질 우위는 아직 비교 검증 전.
- 첨부 피드백에서도 영역별 역할 분리는 장점으로 평가했지만, 나눈 이유와 JSON의 쓰임을 더 설명할 것을 요청함.

## 처리 시간과 다음 계획

- 실제 기업 분석 1건은 약 **8분 8초**. 전처리 35초, 병렬 추출·검증·병합 3분 28초, 최종 브리프 생성 4분 5초. 한 사례이므로 평균 성능으로 일반화하지 않음.
- 따라서 Agent 개수만 줄이면 빨라진다고 단정하기 어려움. 최종 생성 입력량과 CV/JD 중복 추출도 점검할 예정.
- 우선 출처 연결·공통 비교표를 보완하고, ChromaDB·Docker를 연결한 뒤 대표 사례로 검증.
