# 남은 구현 목록

기준: 2026-10-29 · 중간 피드백과 현재 코드 대조. 완료된 로그인·PDF 관리·기존 Agent 실행·결과 저장은 제외했다.

## 핵심 피드백

- [ ] 브리프의 각 사실 항목에 근거 ID·문서·원본 쪽수·절·인용을 연결하고 내용 옆에서 원문을 열기. 없는 근거는 생성하지 않기.
- [ ] 기여 판단에 기업 fact·CV·JD 근거를 연결하고, 사실과 AI 해석을 구분해 표시하기.
- [ ] 기업·직무별 공통 비교표 구현: 사업·전략 / JD 요건 / 연결 경험 / 연결 수준·이유 / 가능한 기여 / 부족한 점 / 근거. 공식 비전·인재상은 확인될 때만 보조 기준으로 사용.
- [ ] 비교 시 CV 버전·보고기간·JD 시점 차이와 자료 부족을 표시하고 비교 결과 다운로드 연결.
- [ ] 상협님과 위 기능에 필요한 구조화 출력·근거 참조 형식 및 JD 없는 분석 방식을 합의. 현재 기여 결과는 Markdown이며 JD가 필수임.

## 2차 서비스 구조

- [ ] ChromaDB에 기업 fact·근거 검색 연결. 전체 fact 입력 대비 검색 누락 여부 확인.
- [ ] Docker/Compose 실행 구성과 환경변수·저장 볼륨·README 정리. 다른 환경에서 실행 검증.
- [ ] 진행 화면에 병렬 추출과 최종 브리프 생성 단계를 구분해 표시하고 경과 시간 안내.
- [ ] 실패·중단 후 재시도/재개 정책 보완. 중복 호출과 무제한 재시도 방지.
- [ ] 같은 CV·JD 추출 결과 재사용 검토. 현재 기여 분석마다 다시 추출하므로 중복 비용·시간이 발생할 수 있음.

## 최종 검증

- [ ] 대표 기업 2~3개와 동일 CV·기업별 JD로 연결 판단·비교 항목·원문 쪽수 및 인용의 정확성 검증.
- [ ] 실제 브라우저에서 PDF 근거 이동·기여 분석·비교·다운로드·삭제까지 확인.
- [ ] Agent 구성 변경은 동일 입력으로 품질·소요 시간·호출 비용을 비교한 뒤 결정. 현재 7개 구성의 우위를 검증한 것은 아님.

OpenDART/JD 자동 수집·관심 기업 기반 성향 분류는 합의된 현재 범위에서 제외했다. 미구현이지만 이번 필수 구현 목록으로 자동 추가하지 않는다.
