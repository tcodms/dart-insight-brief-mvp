# 취업용 기업 브리프 Agent v4

`04_DART_Job_Seeker_Company_Brief_Agent_v4.json`은 Studio 가져오기용 새 초안이다.
기존 Agent, `.env`, 실행 중인 Config ID, UI는 변경하지 않는다.
Studio 업로드·실제 호출과 품질 비교는 아직 수행하지 않았다.

## 입력과 출력

입력은 기존 `merged_company_data.json`이다. 세 FACT Agent의 스키마 변경은 필요 없다.
출력은 문자열과 문자열 배열로 구성된 JSON이며, 기존 근거 연결 형식을 유지한다.
핵심 사업·고객·중요 변화·전략·중대 위험을 먼저 선정하고 고정 목차에 배치한다.
항목 수 고정 배분 대신 중요도에 따라 분량을 조정하며 외부 지식·새 계산·인과관계는 금지한다.

독자 목차는 회사 한눈에 보기 / 핵심 사업과 운영 구조 / 최근 실적과 중요한 변화 /
시장 환경과 경쟁력 / 전략과 투자 / 주요 위험과 대응 / 인력과 조직 / 취업 준비 확인 포인트다.

## 협업 및 서비스 연결 변경점

- 신규 `customers_channels_operations` (`OP01`): 고객·판매 경로·생산/조달/운영 구조.
- 기존 `company_stated_strengths`는 `market_and_competition`에 통합한다.
- 신규 `essential_fact_coverage`: 개발·평가용 필수 FACT 선정 이유와 본문 반영 ID.
  사람의 골든셋과 다르며 최종 사용자 보고서에는 표시하지 않는다.
- 신규 `executive_summary_item_ids`: 상세 본문의 ID를 참조하는 3분 요약 선택 목록.
  별도 요약 문장이 아니라 기존 본문 항목을 재사용한다.
- 기존 `evidence_ids`와 J 카드의 문자열 계약은 유지한다.

현재 렌더러는 새 OP 필드와 요약 ID 목록을 표시하지 않으므로 그대로 활성화하면
새 정보가 화면에서 누락될 수 있다. 서비스 적용 시 렌더러/화면의 목차와 요약 선택을
함께 연결하고 coverage를 독자 본문에서 제외해야 한다.
입력 ID 존재·항목별 근거 연결·coverage/요약 ID 참조 검증도 서비스 적용 시 필요하다.

## 가져오기와 검증

Studio에서 기존 Agent의 설정을 덮어쓰기보다 별도 초안으로 가져와 비교한다.
가져오기 후 instruct→extract 연결, 출력 스키마와 프롬프트, 사용 모델을 확인한다.
이 파일은 기존 내보내기의 파싱/파이프라인 설정을 계승하며 원격 Agent/Config 식별자는 제거했다.
Studio 가져오기 호환성은 실제 업로드로 확인해야 한다.

같은 FACT 입력으로 기존 버전과 비교하고, 입력에 존재하는 필수 사실 보존·조건 정확성·
근거 충실성·이해도·중복을 평가한다. 원문에는 있으나 FACT에 없는 사실은 추출 피드백으로 분리한다.
Agent의 자기 점검만으로 품질 개선을 확정하지 않는다.

재생성: 저장소 루트에서 `python build_company_brief_agent_v4.py`.
