# Business Strategy Agent 범용 설명 v5

작성일: 2026-11-02

대상: `01_DART_Business_Strategy_Extract_Agent_description_v5.json`

사용자가 첨부한 Downloads의 v4를 기준으로 기존 description 값 17개만 변경했다. 23개 필드의 이름·순서·자료형, 스키마 구조, 노드·파서·manyRows·연결 설정과 exportedFrom 메타데이터는 그대로다. 파일명 v5는 로컬 개선안이며 원격 Config 버전이 아니다.

## 설명 변경

- 수익구조: 매출뿐 아니라 금융의 영업수익·이자/수수료 수익과 서비스 수익을 원문 표제대로 추출하도록 보완했다. 잔액·자산·조달 규모·이익을 수익으로 혼동하지 않게 하고, 빈 배열 전 수익 표 재확인을 명시했다.
- 업종 중립성: 제조·금융·소프트웨어/서비스의 대응 표현을 조건부 예시로 제시했다. 적응증·임상·허가·급여 등은 해당 업종과 원문에 실제 존재할 때만 적용한다.
- 중복: 내부 시스템, 외부 고객 서비스, 실제 신규 사업, 구조적 연혁, 향후 확대를 구분해 같은 사건을 담당 필드 하나에 배치한다. 공식 용어 색인의 명칭 재사용은 허용하되 대소문자·표기 변형 중복을 줄인다.
- 신규성: 전년도 출시·과거 법인 설립·정관 목적 추가를 보고기간 실제 신규 사업 개시와 구분한다.
- 근거: 기존 ID와 evidence_refs 문자열 계약을 명시적으로 유지한다. 페이지를 넘긴 내용을 한 페이지로 표시하지 않고 원문 용어·한글/한자·숫자를 변형하지 않도록 했다.
- 한계: `_ctx`·locator 등 내부 처리정보와 이미 해결된 표지 날짜 문제를 사용자 제한사항으로 출력하지 않도록 보완했다.

## 형식 및 병합 검증

1. 재귀 비교로 변경 경로 17개가 모두 기존 description 값임을 확인했다. 다른 키·순서·값·자료형은 원본과 동일하다.
2. 고정된 23개 필드 스키마와 기존 근거 키·구분자·정수 original_page 계약을 유지했다.
3. 저장돼 있던 실제 녹십자·기업은행·기아 출력의 스키마와 기존 병합 함수를 재검사했다. Business 입력만 넣고 다른 두 배치는 같은 메타데이터의 빈 입력으로 분리 검증했다.
4. 녹십자 88개, 기업은행 54개, 기아 90개 항목이 병합됐다. 기업은행은 이전에 관측한 완전 중복 제거 경고 2건이 동일하게 발생했다.

위 재검사는 기존 출력 계약을 보존했는지 확인한 것이다. v5 Agent의 실제 출력이나 세 실제 Agent·최종 브리프 생성 전체를 검증한 결과가 아니다. 설명만으로 형식·정확성을 강제할 수 없으므로 Python 검증을 유지한다. 이번 작업에서 외부 Agent 재호출은 하지 않았다.

## 적용

Studio에서 현재 Business Strategy Agent에 설명을 적용하거나 파일을 가져온 뒤 저장/게시한다. 원본 exportedFrom에는 이전 식별 메타데이터가 남아 있으며 운영 Agent를 자동 갱신하지 않는다. 적용 후 실제 Agent ID·Config ID를 확인해 `.env`의 Business Strategy 두 항목에 맞춘다. API 키·병합 코드·다른 Agent 설정은 이번 작업에서 변경하지 않았다.

적용 후 같은 세 기업 PDF로 금융 영업수익 누락, 중복, 신규성·기간·주석, 페이지 인용, 병합 호환성을 다시 비교해야 한다. 실제 추출 품질·시간·사용량 개선은 아직 확인하지 않았다.
