# Business Strategy Agent 설명 강화안

작성일: 2026-11-02

대상 파일: `01_DART_Business_Strategy_Extract_Agent_description_v4.json`

사용자가 제공한 `DART Business Strategy Extract Agent.json`을 기준으로 기존 description 값 17개만 변경했다. 23개 출력 필드의 이름·순서·자료형, 노드·연결·파싱 설정, manyRows 옵션, 스키마 구조, exportedFrom과 원격 Config 메타데이터는 그대로 유지했다. 파일명의 v4는 로컬 개선안 이름이며 원격 Config 버전을 뜻하지 않는다.

## 반영한 개선

- 사실 ID와 근거 ID의 일대일 대응, 기존 evidence_refs 문자열의 키·순서·구분자와 정수 원본 페이지 규칙을 명시했다.
- 표의 머리글·단위·주석을 함께 확인해 보고부문 합계를 특정 부문 매출로 잘못 귀속하지 않도록 했다.
- 주체·연결/별도·기간·투자 주석을 보존하고 지주회사/종속회사 정보를 보고회사 정보로 옮기지 않도록 했다.
- 프로젝트·계약·판매경로는 근거가 충분한 독립 항목으로 분리하고 일부만 인용하는 것을 금지했다.
- 과거 설립과 보고기간 신규사업, 계획·현재 진행·신청·승인·반려를 구분했다.
- 구체적인 채널 확대 수단과 진행 중인 투자를 점검하고, 분야별 투자계획 없음을 회사 전체 전략 부재로 확대하지 않도록 했다.
- R&D 비용·비율의 중복과 내부 파서/locator 정보의 limitations 노출을 억제했다.

## 적용 시 주의

첨부 원본의 exportedFrom Agent ID는 직전 검증에서 현재 본인 API 키로 404를 반환했고, 현재 `.env`의 Business Strategy Agent와도 다르다. 이 파일은 가져오기용 설명 개선안이며 다운로드만으로 운영 Agent가 업데이트되지는 않는다. 원본 메타데이터는 요청에 따라 수정하지 않았다.

Studio에서 파일을 가져오거나 현재 Business Strategy Agent에 설명 변경을 적용한 뒤 저장/게시하고, 실제 Agent ID·Config ID를 확인한다. 필요한 경우 `.env`의 `BUSINESS_STRATEGY_AGENT_ID`와 `BUSINESS_STRATEGY_CONFIG_ID`만 실제 값에 맞춘다. 다른 Agent·API 키·병합 코드는 이번 작업에서 변경하지 않았다.

## 검증 결과와 한계

- JSON 파싱과 재귀 비교 통과: 변경된 경로 17개 모두 기존 description 값이며 나머지 키·순서·자료형·값은 원본과 동일하다.
- 기존 사실·근거 파서가 설명에 사용한 표준 문자열과 여러 줄 quote 예시를 처리하는지 확인했다.
- 프롬프트 설명의 변경이므로 실제 추출 개선이나 반복 실행 안정성은 아직 측정하지 않았다. 외부 Agent를 재호출하거나 새 추출 결과를 생성하지 않았다.
- 적용 후 같은 PDF로 단독 호출하여 매출 소계 귀속, 투자 주체 주석, 프로젝트별 인용 완전성, 전략 누락, 중복을 기존 결과와 비교해야 한다. 설명만으로 스키마 준수나 사실 정확성을 보장할 수 없으므로 Python 검증을 유지한다.
